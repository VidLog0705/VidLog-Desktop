# VidLog · 电脑端

电商打包取证系统的**电脑端**：工位录像、集中接收手机/其他电脑的录像、检索与回放。

C# / .NET 9 + WPF。

**闭源商业产品。** 本仓库为私有仓库。

---

## 当前进度

**M0 骨架 · M1 契约 · M2 录像链路 · M3 检索与回放 · M5 接收端** —— 逻辑部分都已落地。
桌面端现在**只差真机验收**和两处如实标注的缺口（见下）。

已落地：

- **M1**：`RelativePath` / `WaybillNumber` / `ContentHash` 三个硬约束值对象；
  三个状态机枚举（规格 §4）；单号归一化（§3.2.3）
- **M2 扫码**：扫码枪按键判定（§3.2.1），含键盘自动重复防护；
  **Windows 全局键盘钩子**（窗口失焦时扫码枪照样打进来）
- **M2 取景识码**：摄像头识码（§3.2.1 的第二种入口，ZXing.Net，Apache-2.0）；
  相机是独占的，所以识码与采集之间**先放设备再开录**（实测）
- **M2 媒体**：编码能力**实测探测**（§3.1.5）、MKV→MP4 无损 remux、
  **实际解码校验**（§3.1.4）
- **M2 收尾**：`SessionFinalizer` —— 不变量 I9 的唯一入口，七种停法全走同一条路径；
  孤儿分段自动收尾（§3.1.1）；磁盘余量守卫（§3.1.1）
- **M2 入库**：SHA-256 内容哈希（§3.6.1）+ JSON Lines 索引，只存相对路径（§6.2）
- **M3 检索**：**WPF 原生检索界面** —— 单号（精确/前缀/模糊）+ 日期 + 发货退货筛选（§3.8）；
  可修正标签（I5 落点）
- **M3 回放**：跨分段时间轴 + **跳转到打点位置**（§3.8）
- **M3 网页回放**：局域网 HTTP 服务，检索页 + Range 视频流，零外部资源（I10）
- **M5 接收端**：`/api/v1/*` —— 探针续传（不自己记进度）、分片、**原子发布 + 签名回执**、
  配网与**人工批准**入网、设备凭据签发（§3.4.2 / §3.4.4 / §3.4.5）
- **M6 前置**：归档后端抽象 + 保留期**判定层**（§3.5）——判定与审计写完了，
  **执行层没有触发点**（见下）
- **托盘 / 后台运行**：关窗口不退录制，回到托盘

启动即用：应用会先收尾上次没走完的录像，再起回放服务，地址显示在主窗口上。

> ⚠️ 上面这句在 2026-09-23 之前**是假的** —— 那一步从没被调用过，于是孤儿永不被收尾、
> 回放服务从没起来过、「局域网回放页」按钮永久禁用；而同一批里**编排循环也没被启动**，
> 后果是整场只录一个永不滚动的分段。三处都已修，原因与教训见
> [`docs/实现决策.md`](docs/实现决策.md) §28。

### ⚠️ 未完成之一：真机验收

代码路径都用真 FFmpeg 端到端验过，**摄像头那两条已经在真机上跑过了**（§22），剩下的还没有：

| 验收项 | 状态 |
|---|---|
| M2：录一段，产物能被系统播放器直接播放 | ✅ **真摄像头**端到端验过（录 13 秒、滚 3 段、三段各自真实解码校验） |
| M2：录制中强杀进程 → 重启后自动收尾 | ✅ 真 FFmpeg 端到端验证通过 |
| M2：磁盘写满 → 提前告警 + 主动收尾 | ⚠️ 逻辑与边界已测（`DiskSpaceGuardTests`），**没在真写满的盘上跑过** |
| M3：网页端**从另一台设备**能打开并回放 | ⚠️ 服务确实绑在所有网卡（实测监听在 `::`），**没真拿第二台设备连过** |
| M5：手机端上传 → 电脑端收到并入库 | ⚠️ 接收端逻辑已测，**没和手机端真联过** |

按 `AGENTS.md` §9：**编译全绿但真机行为错误的问题，只有真机能暴露。**

### ⚠️ 未完成之二：明确知道做不了的

**静止停录 / 三种工作模式的自动停录** —— 不是「缺时间」，是被实测挡住：
录制中相机是独占的，多开一路取帧会堵住管道，而堵住管道会一路顶到 ffmpeg，
它连 `q` 都处理不了（§24、§25）。所以**界面上如实标着它不生效**，
而不是留一个改了没反应的开关（踩坑 #13）。候选路子与它为什么还不能做，见 §28.5。

**还没动的**：预录缓冲（§3.1.3）、§3.2.5 的三项异步联动
（重复单号检测 / 订单联动 / 退款拦截）。

**清理的执行层没有接线** —— `Cleanup/` 的判定层（豁免 + 回查 + 审计流水）写完也测过了，
但**一个生产调用点都没有**。判定口径本身已经对上了 §3.5.2.1
（保留期自**归档成功时刻**起算，用回执里的 `TimeAnchor`），
缺的是**谁来提供那张归档时刻表**：`ReceiptStore` 只有按 id 查一个的 `FindAsync`，
要接上第一步是加 `LoadAllAsync` —— **现在故意不加**，理由写在 `CleanupPlanner` 的类注释里。
**今天不会有任何文件被删。**

⚠️ 而**另一头卡得更死**：§3.5.1 规定归档层 = 本机磁盘时**不提供清理选项**，
所以「归档层」那个下拉得先能切到 NAS / 网盘 —— 而那两个后端**都还没有实现**
（`Cleanup/` 里只有 `LocalFolderArchiveBackend`）。**只要它们不存在，
清理在电脑端永远开不了**，与接线无关。

详见 [`docs/实现决策.md`](docs/实现决策.md) §6、§13 与 §28。
