## 2. ★★ 真机测试清单（那台机器能做、本机做不了的）

**本机一条录像都没有、一台 dshow 设备都没有**（`ffmpeg -list_devices` 报
`Could not enumerate video devices` / `audio only devices`，`Get-PnpDevice` 无摄像头）。
所以下面这些**全是「代码写了、没在真设备上跑过」**的。按可疑度排：

### 2.1 真录制全链路（最要紧 —— 本机从来没验过真录制）

本机所有录制用例走的是**假采集**（`FakeCapture`），真 ffmpeg 那半只有
`FfmpegCameraCaptureIntegrationTests`（两条，本机一直跳过）。

要验：真开相机 → 录一段 → 停 → remux → 真解码校验；
再看产物里的**音轨**（2.1 加的 `-map`/`-an`）、**方向**（2.3 加的四档）、
**分辨率**（起录时探测落的那一档）。

```powershell
$env:FFMPEG_EXE='...\ffmpeg.exe'
& H:\dotnet\dotnet.exe test VidLog.Desktop.sln -c Release --filter "FullyQualifiedName~FfmpegCameraCaptureIntegrationTests"
```

### 2.2 预览那一档（dshow）

**§54 验过「一路源两路输出」，但那是 1 fps 灰度**（识码用）；
`PreviewProcess` 出的是 **12 fps 彩色**，本机只量过 **RTSP 源**的吞吐
（12.1 fps / 目标 12，见 `PreviewThroughputTests`）。**dshow 那一档没验**。

要验：`PreviewProcess.StartAsync` 对着真摄像头能不能起来、帧读不读得过来、
**停了之后相机有没有真的放开**（没放开的话紧接着的录制会拿到 `device already in use`）。

### 2.3 真麦克风的音轨（2.1）

本机**没有麦克风** ⇒ 验过的只有：坏音频设备 1.0 秒退出、不去开视频设备、
不产出文件（§64）。**没验**：

- 真麦克风录出来的文件里**到底有没有音轨**（用 `ffprobe` 看流，或听）。
- **麦克风被别的程序占用**时的行为（规格要的是：照常录视频、只是这一段没音轨）。
- **网络摄像头 + 本机麦克风同时用**（`-map 1:v:0 -map 0:a:0`）—— argv 已被绊线覆盖，
  但**真录出两条流**没跑过。

### 2.4 方向四档的画面（要人眼）

`hflip,vflip` 与两个 `transpose` 的**滤镜语义**验过（像素级），
但「真机上画面转对了没有」只能人眼对着实景看。
⚠️ 也顺手确认**水印的字是正的**（规格 §3.1.7 ②：水印随方向）——
水印排在旋转之后，而那条顺序只在 argv 上有绊线、没在画面上看过。

### 2.5 规格探测 + 「原生档回落」（批次 3 的步 4）

### 2.6 扫码枪（批次 3 的步 6）

`Code128` 的**码表靠 ZXing（影像式）往返验证**过 ⇒ 图形本身是对的。
**没验**：工位上那把枪能不能扫**屏幕上的**条码 —— 若它是**激光式**，
扫屏幕常常失败（屏幕发光、激光反射）。那属于产品设计要面对的事实，如实记录即可。

### 2.7 相机独占 vs 识码（§25 / §54 的老问题）

设计图要求「录制中也有实时画面」。本机没设备 ⇒ **一次都没验过**。
§62 给了结论：**「预览一个进程 + 录制一个进程」走不通**（相机独占），
预览必须做成**采集进程的第二路输出**（§54 验过 1 fps 灰度那一档）。
⚠️ 主窗口那个「实时预览未接入」就是这么留下的 —— 它要等这一条验通。

### 2.8 多磁盘 / 预留空间（**并进批次 4 做完了**，§82）

设计图 `_43` 上的两张表（保存位置 / 备份位置，各带预留空间）现在真的动到了
**成品选址**这条核心路径。⚠️ 图上那两条规则抄在 `ReservedSpace`：
系统盘 `max(30GB, 10%)`、其他盘 `max(20GB, 5%)`（**图上的数字证实了这个解读**）。

要验（**都要真磁盘，且会真的写文件**）：
- 插两块盘 → 列表顺序 → 前一块写不进去时**真的换到下一块**。
- **预留空间真的留住了**（塞到只剩预留量时不再往里写）。
- ⚠️ **那块盘拔掉之后**（盘符消失）的表现：按 §82 的口径应当**不删、并报查不了**。

## 6. 流程

- **CI 是 push 触发**（`.github/workflows/ci.yml`）。每批做完 push 一次看绿再往下。
- ⚠️ **跳过守卫**：CI 会读 TRX 里被跳过测试的 **Skip 原因**，
  带 `[允许跳过]` 标记的才放行（`tests/…/SkipMarker.cs`）。
  新增一条「本机跑不了」的用例时，**用 `SkipMarker.Allow(...)` 包一下 Skip 文案**
  —— 不加的话 CI 会「测试全过但守卫红」，而那很难看出来。
  ⚠️ **`RequiresFfmpegFact` 不许打这个标记**（FFmpeg 缺了就是环境配错，必须红）。
- 提交信息写**为什么**（母仓 `AGENTS.md` §6）。
- 本仓 `docs/实现决策.md` 是**决策与教训的唯一落档处** —— 遇到「为什么这么写」
  先在那儿搜；做了新决定就往后面加一节（编号接着排）。
